## 1. Product framing
TPUB = the Tukhnanutha group's digital out-of-home (DOOH) advertising network in Tunisia. The website is both (a) the marketing site that explains TPUB and converts advertisers, and (b) the client space where advertisers ("annonceurs") log in and run campaigns end to end: create → pick zones & screens → creative → submit → AI moderation → admin validation → broadcast → follow-up. Plus a light back-office for TPUB staff (ADMINISTRATEUR / SUPERVISEUR / OPERATEUR) — without admin validation nothing ever airs, so it is required for a working demo.
Language: **French only** (`<html lang="fr">`), Tunisian context (TND, `fr-TN`, Africa/Tunis). TPUB is pre-launch ("concept/pre-build"): never invent screen counts, client names, audience figures, ROI, or prices. Follow the guardrails in `docs/tpub-brief.md`.

## 3. Architecture
### 3.1 Backend bridge + session (security model)
- Browser only ever calls same-origin `/api/...`. `NEXT_PUBLIC_*` backend URL is forbidden.
- `src/app/api/[...path]/route.ts`: proxies GET/POST/PUT/DELETE/PATCH to `${process.env.TPUB_API_URL ?? "http://localhost:8080"}/api/<path>` (read env inside the handler). Adds `Authorization: Bearer <token>` from the **httpOnly cookie `tpub_token`**. Refuses `/api/auth/*` (404 JSON) — auth goes through the session routes. Forwards query string, body, content-type, abort signal; strips hop-by-hop headers; unreachable backend → 502 JSON `{status:502,message:"Le service TPUB est momentanément indisponible."}`. Empty-body 403 from Spring while a token cookie exists → respond 401 JSON `{status:401,message:"Session expirée"}` and clear cookies.
- Session routes (`src/app/api/session/...`): `POST login` (calls Spring `/api/auth/login` WITHOUT Authorization header), `POST register` (`/api/auth/register`), `POST logout` (clear), `GET` (returns `{user}` or 401). On success set `tpub_token` (httpOnly, sameSite lax, secure in production, path /, maxAge = JWT exp − now, fallback 24h) and `tpub_user` (httpOnly, JSON `{email, nom, role, userId, exp}`), return `{user}` (never return the token to the browser).
- `src/lib/session.ts` (server-only): `getSession()` reads + validates cookies (expired → null). `src/middleware.ts`: `/espace/**` requires any session with role ANNONCEUR (other roles → `/admin`); `/admin/**` requires ADMINISTRATEUR|SUPERVISEUR|OPERATEUR (ANNONCEUR → `/espace`); unauthenticated → `/connexion?next=<path>`. `/connexion` & `/inscription` with a valid session → redirect to the role's home.
- `src/lib/api/client.ts` (browser): `apiFetch<T>(path, {method, body, signal})` → typed `ApiError {status, message(fr), fieldErrors?}` / `ApiTransportError`. Parses JSON only when content-type is JSON and body non-empty. Translates Spring English messages & Bean Validation messages to French (`src/lib/api/messages.ts` map, incl. every business message in contract §4). On 401 → dispatch a single `tpub:session-expired` event → shell redirects to `/connexion?next=…&expire=1`. Never surfaces "Failed to fetch" or raw English.
- `src/lib/api/types.ts`: every request/response interface + enum union from the contract (verbatim names). `src/lib/api/endpoints.ts`: one typed function per endpoint used by the UI (campaigns, ai, admin, zones, supports, reservations, statistics, emergency, diffusion). Normalise lowercase `AiReportResponse.aiStatus` / `DiffusionResponse.type` to uppercase in the endpoint layer.
- `src/lib/format.ts`: `formatTND(n)` (`Intl.NumberFormat("fr-TN",{style:"currency",currency:"TND"})`), dates `fr-TN` long/short, `toApiTime("08:00") → "08:00:00"`, `fromApiTime`. `src/lib/campaign-status.ts`: label, tone (info/warning/blue/success/muted/danger), step index for the stepper, derived states ("Programmée" if ACTIVE && startDate>today, "Terminée" if endDate<today), `isEditable` (BROUILLON|REJECTED_BY_AI), `canSubmit` (BROUILLON), `isDeadEnd` (REJECTED_BY_AI → offer "Dupliquer").
- Client data hook `src/lib/use-resource.ts`: `useResource(key, fetcher)` → `{data, error, loading, reload}` with AbortController and StrictMode double-call guard. No global store.

### 3.4 Campaign wizard (`/espace/campagnes/nouvelle`) — enforce backend ordering (contract §6)
Step 1 "Votre campagne": name, objective (help: it is what the AI moderation reads), budget (TND ≥ 0), période (startDate ≥ today, endDate ≥ startDate), plage horaire (endTime > startTime; send HH:mm:ss). "Enregistrer le brouillon" → `POST /campaigns` (store id in URL `?id=` so refresh resumes; subsequent edits `PUT`).
Step 2 "Zones & écrans": `GET /zones/active` + `GET /supports` (filter `technicalStatus === "ACTIF"`); pick zone chips → screens as selectable cards (type, zone, capacité); per selected screen `POST /reservations` with the SUPPORT's own zoneId and the campaign dates/times; show conflicts ("Support déjà réservé sur cette période") inline per screen; already-created reservations listed via `GET /reservations/campaign/{id}` (no cancel endpoint → say "réservation temporaire, confirmée à la validation"). At least one reservation required to continue.
Step 3 "Créatif": dropzone accepting image/video with local preview + format guidance (16:9 & 9:16, durée 10 s) and an honest notice: "Le dépôt de fichiers sera activé prochainement — votre conseiller TPUB récupère le visuel après validation." Nothing is uploaded. Optional step (can skip).
Step 4 "Vérification & envoi": recap (facts, screens, estimation coût = sum estimatedCost, vues estimées = campaign.estimatedViews), checklist of moderation rules (no misleading "gratuit/garanti" claims etc. from brief), "Soumettre à la modération" → `POST /campaigns/{id}/submit` then `POST /ai/check-content/{id}` with an animated analysis state (can take seconds) → result panel: approved (success, "en attente de validation TPUB"), review_required (warning, issues + recommendation), rejected (danger, issues, CTA "Dupliquer et corriger"). Then link to detail page.

## 4. Quality bar (every builder)
- Server components by default; `"use client"` only on interactive leaves. Marketing pages export `metadata`.
- Accessibility: skip link, landmarks, one h1 per page, visible focus ring (blue-text 2px offset), labels on every control, `aria-live` for async results, 44px touch targets, reduced motion respected (CSS + JS), color is never the only signal (status pills have text), contrast per tokens. Keyboard: dialogs trap focus, menus close on Escape.
- Responsive mobile-first; test mentally at 360, 768, 1280. No horizontal overflow. Tables become cards < md.
- Reveal/entrance animations MUST render content fully visible when `prefers-reduced-motion: reduce` (screenshots are taken with reduced motion) and when JS is disabled for server-rendered marketing content (use CSS class toggled after mount, not inline `opacity:0` in SSR HTML without a no-JS fallback).
- No literal hex colours in components (use tokens/utilities); no `dangerouslySetInnerHTML`; no English UI text; no invented metrics; no `any`.
- Every async screen has loading skeleton, error state with retry (different message for 502 unreachable vs 401 vs 400), and empty state with one clear action.
- Do NOT run `npm install` or add dependencies in phase 2 (report needs instead). Do NOT run `next build`/`next dev` in phase 2 (shared `.next`). Verify with `npx tsc --noEmit -p .` and `npx eslint <your files>` and `npx vitest run <your tests>`.
- Write at least one focused unit test for non-trivial logic you add (e.g. wizard validation, status mapping, KPI aggregation) under `src/**/__tests__/`.

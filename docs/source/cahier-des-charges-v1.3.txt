1. Introduction & Objectif du Projet

Ce document constitue le cahier des charges de TPUB, une plateforme intelligente de gestion,
diffusion, monétisation et contrôle publicitaire développée dans l’écosystème Tukhnanutha Holding.
Le projet TPUB vise à fournir une solution web complète permettant aux annonceurs de créer des
campagnes publicitaires, de choisir les zones de diffusion depuis une carte interactive, de consulter
la disponibilité des supports selon le temps, de réserver des créneaux publicitaires, de faire vérifier
automatiquement les contenus par une IA avant autorisation, puis de suivre les performances de
leurs campagnes.
Vision du produit : TPUB centralise la publicité numérique et physique connectée à travers une
plateforme capable de gérer les annonceurs, les campagnes, les zones, les supports, les créneaux
horaires, les statistiques, les alertes prioritaires, l’analyse IA des contenus et la diffusion intelligente.
La distinction fondamentale du projet réside dans son moteur intelligent de sélection publi-
citaire et son module IA de filtration et vérification du contenu. Avant toute diffusion,
le contenu publicitaire est analysé automatiquement afin d’identifier les risques, les anomalies, la
qualité du message et la conformité aux règles internes. Ensuite, le moteur décide quelle publicité
doit être diffusée selon la zone, le temps, la disponibilité, le budget, le type de support, la priorité
et les règles d’urgence.

Convention de lecture
MVP : fonctionnalités obligatoires constituant la base irréductible du projet.
BONUS : fonctionnalités avancées renforçant la valeur académique, technique et professionnelle
du PFE.

2. Périmètre Fonctionnel Global

TPUB doit être développé comme une plateforme web composée de plusieurs espaces fonctionnels :

    — un espace administrateur TPUB ;

    — un espace client annonceur ;

    — un module de création et gestion des campagnes ;

    — une carte interactive de choix des zones de diffusion ;

    — un module de disponibilité temporelle et réservation ;

    — un module de gestion des supports publicitaires ;

    — un module IA de filtration et vérification du contenu avant autorisation ;

    — une API de vérification IA du contenu ;

    — une API de diffusion intelligente ;

    — un moteur de décision publicitaire ;

    — un module d’urgence prioritaire ;

    — un tableau de bord de statistiques et revenus.

3.5 IA de Filtration & Vérification du Contenu

Ce module permet d’analyser automatiquement les contenus publicitaires avant leur autorisation
de diffusion. Il agit comme une couche de contrôle intelligente entre la création de la campagne par
le client annonceur et la validation finale par l’administrateur TPUB.
[MVP]

    — analyse automatique du texte de la publicité ;
    — analyse automatique des images publicitaires ;
    — analyse automatique des vidéos ou des miniatures vidéo ;
    — extraction du texte intégré dans les images par OCR lorsque cela est possible ;
    — détection des contenus non conformes aux règles internes de diffusion ;
    — détection des mots interdits, messages trompeurs, contenus sensibles, incohérents ou non

        professionnels ;
    — attribution d’un score de risque au contenu ;
    — attribution d’un score de qualité publicitaire ;
    — génération automatique d’un rapport de vérification ;
    — classification du contenu selon trois états : autorisé, à vérifier manuellement ou refusé ;
    — blocage automatique de toute campagne non analysée ou non validée ;

    — affichage du résultat de vérification dans le dashboard administrateur ;

[BONUS]

Règle fonctionnelle importante
Aucune campagne publicitaire ne doit être autorisée à la diffusion sans passer par le module IA de
filtration et de vérification. L’IA assiste l’administrateur en détectant les risques, les contenus non
conformes et les anomalies. La décision finale reste toujours sous le contrôle de l’administrateur
TPUB.

Exemple de fonctionnement attendu

    1. Le client ouvre le formulaire de création d’une campagne.
    2. Il ajoute le contenu publicitaire.
    3. TPUB lance l’analyse IA du contenu.
    4. Il sélectionne une zone sur la carte, par exemple Tunis Centre avec un rayon de 3 km.
    5. Il choisit la période : du 01/06/2026 au 07/06/2026.
    6. Il choisit les horaires : 08h00 - 20h00.
    7. TPUB affiche les supports disponibles, occupés ou en maintenance.
    8. Le client sélectionne les supports disponibles.
    9. Le système calcule le budget estimé et le nombre d’affichages estimés.
   10. La campagne passe en statut « en attente de validation ».
   11. Après validation par l’administrateur, les créneaux deviennent réservés.

4.2 Règles de Priorité

Priorité  Règle
1
2         Si un message d’urgence actif concerne la zone, il est diffusé avant
3         toute publicité.
4         Si une campagne est confirmée et réservée sur ce support à cet horaire,
5         elle devient candidate.
6         Si plusieurs campagnes sont candidates, le système applique le score
          de priorité et le budget.
          Si les scores sont équivalents, le système applique une rotation équi-
          table.
          Si la campagne n’est pas approuvée par l’IA et par l’administrateur,
          elle est exclue du moteur de diffusion.
          Si aucune campagne n’est disponible, le support affiche un contenu
          par défaut.

4.3 Contrôle IA avant Diffusion

Avant qu’une campagne devienne candidate pour la diffusion, le moteur intelligent doit vérifier son
statut de validation IA.
[MVP]

    — une campagne avec un contenu non analysé ne peut pas être diffusée ;
    — une campagne refusée par l’IA ne peut pas être diffusée ;
    — une campagne signalée comme risquée doit passer par une validation manuelle ;
    — une campagne validée par l’IA et par l’administrateur peut entrer dans le moteur de diffusion ;
    — le score IA peut influencer la priorité et la fréquence de diffusion ;
    — toute décision IA doit être enregistrée dans les logs.

Règle de décision

SI campaign.ai_status = "approved_by_ai"
ET campaign.admin_status = "validated_by_admin"
ET campaign.reservation_status = "confirmed"
ALORS la campagne peut etre diffusee.

SINON la campagne reste bloquee.

11. Scénario de Démonstration Attendu

Pour valider le PFE, l’étudiant doit préparer une démonstration complète :

    1. un client annonceur crée un compte ;
    2. il crée une campagne publicitaire ;
    3. il ajoute une image ou une vidéo ;
    4. l’IA analyse automatiquement le contenu ;
    5. le rapport IA est généré ;
    6. l’administrateur consulte le rapport IA ;
    7. le client ouvre la carte interactive ;
    8. il sélectionne une zone de diffusion ;
    9. il choisit une période et des créneaux horaires ;
   10. TPUB affiche la disponibilité des supports selon le temps choisi ;
   11. le client choisit les supports disponibles ;
   12. le système estime le budget et les affichages ;
   13. l’administrateur valide la campagne après analyse IA ;
   14. un support appelle l’API de diffusion ;
   15. le moteur sélectionne la bonne publicité ;
   16. les statistiques sont mises à jour ;
   17. un message d’urgence est créé ;
   18. le message d’urgence remplace temporairement la publicité normale.

Les fonctionnalités obligatoires constituent la base irréductible du projet. La carte interactive,

13. Conclusion

La version MVP de TPUB doit permettre de démontrer une plateforme web complète, profession-
nelle et évolutive. L’étudiant doit se concentrer sur la création d’un système fonctionnel où un
annonceur peut créer une campagne, importer son contenu, déclencher une analyse IA, sélectionner
sa zone depuis une carte, vérifier la disponibilité des supports selon la date et l’heure, réserver les
créneaux disponibles, puis suivre les performances après validation et diffusion.

Le résultat final attendu est une plateforme capable de prouver le fonctionnement du modèle TPUB :
publicité ciblée par zone, disponibilité temporelle, réservation intelligente, vérification
IA du contenu, diffusion contrôlée, statistiques et priorité aux messages d’urgence.
